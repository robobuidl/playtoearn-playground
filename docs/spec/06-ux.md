## 1. Principles

| ID | Rule |
|---|---|
| UX-P-1 | Two taps to a ready game (lobby card, Play). The first ranked run of an iframe session starts with a tap inside the frame; later runs start from Play again (UX-RUN-3). Tips never gate |
| UX-P-2 | Cost before commitment: every control that can start a ranked run names its cost in visible text and accessible name ("free try", "ad try", "{cost} points"); points are never spent without a tap on such a control (R1.3) |
| UX-P-3 | Never charge for our failures: load, start, ad and network failures keep tries and points (R1.7); failure copy says what it cost ("No try was used") |
| UX-P-4 | Mobile portrait first, one thumb: primary CTA in the bottom third, pseudo-fullscreen game mode |
| UX-P-5 | Honest numbers: only real deadlines (daily reset, weekly close, claim deadline), "If the week ended now" for provisional values, "about" for estimates |
| UX-P-6 | Words live in the shell; canvases draw digits and icons only (R8.1) |
| UX-P-7 | The server is the truth: the UI never computes rewards, ranks, Trophies, tries, eligibility or bonus amounts; the TryGate only selects UI from `TryStatus` |
| UX-P-8 | Calm by default: no auto-start into paid tries, no auto-played ads, no nagging, no confirmshaming, no loss framing on a screen with a paid control |
| UX-P-9 | Always show the path: next target, top 100 cutoff, reset time |
| UX-P-10 | WCAG 2.2 AA for all shell UI, light and dark |

## 2. Routes and vocabulary

History API routing under attribute `base-path` (default `/playground`); `routing="hash"` (artifact demo) maps `/playground/a/b` to `#a-b`. Host routing: UX-HOST-11.

| Route | Screen | Access |
|---|---|---|
| `/playground` | S1 Lobby | public |
| `/playground/g/{gameId}` | S2 Game page; history state `#play` while S8 is open in overlay mode | public, ranked needs login |
| `/playground/leaderboards[/{gameId}]`, `/playground/leaderboards/all-games` | S10 hub or per-game board, S11 (`?week=2026-W39`, `?view=around`) | public |
| `/playground/results/{weekId}` | S12 reveal (also a sheet) | user |
| `/playground/me` | S13 (`?tab=week, rewards, runs, spending, updates, settings`) | user |
| `/playground/how-it-works`, `/playground/rules` | S14 (`#faq-{id}`), S15 (`?week=`, `#r-{n}`) | public |
| admin origin (UX-ADM-0) | S19 `<p2e-admin>` | staff roles |

UX-IA-1: every (i) deep-links to an S14 or S15 anchor. UX-IA-2: no personal data in URLs; share links are the plain game URL. UX-IA-3: notices deep-link to a screen and never start a run.

UI terms: try, free try, ad try, points try; run, ranked run, practice run, chip "Practice"; Weekly leaderboard, All-Games Leaderboard (tab "All-Games"); Trophies and Community Bonus exactly so, never "points" for Trophies; P2E Points (long), points (short, with the points icon); Plus, PlayToEarn Plus. Banned words: UX-COPY-1.

Eligibility reasons from spec 01: ACCOUNT_TOO_NEW `accountTooNew`; every review or fraud HOLD (REVIEW_PENDING, DEVICE_REVIEW, REGION_MISMATCH and later additions) `review`, shown neutrally (UX-FAIR-2); REGION_PRIZES_BLOCKED `region`; AGE_NOT_CONFIRMED `age`; STAFF `staff`; DUPLICATE_DEVICE_ACCOUNT `deviceLimit`; ACCOUNT_BANNED, DISQUALIFIED `rewardsBlocked`. UX-HOST-EV-1: a cancelable event's default runs unless a listener calls `preventDefault()`. The host SHOULD map login to `playToEarnAuth.showLogin()` and balance to `.setPlayToEarnUserPoints`.

## 5. Flows

### 5.1 Run lifecycle

UX-RUN-1: stage mode `overlay` (pseudo-fullscreen modal `<dialog>`, top layer) when `(hover: none) and (pointer: coarse)`, viewport width < 1024 px, or app mode; else `inline`. Fixed when S2 mounts.

UX-RUN-2: the game iframe lives in the stage and is never moved in the DOM (a moved iframe reloads); in overlay mode the closed stage `<dialog>` exists inside S2 from the start. The iframe SHOULD be created when S2 is idle (pre-warm), except with Save-Data or 2G, and is destroyed when S2 unmounts. `InitParams` (spec 03): `appMode`, `locale`, `strings.tapToStart` (`stage.tap` or `stage.click`), audio from `LocalPrefs`, `reducedMotion`, `haptics`, `heroSkin` (from `GameDetail.heroSkin`).

UX-RUN-3 (R1.7, spec 03 SDK-LC): the shell uses spec 03 section 8.1 messages verbatim. After an arming tap (UX-RUN-4) it sends `arm {mode, weeklyBest, hostTap}`, with `hostTap: true` for every run after the first of the iframe session (the S9 or S5 tap is then the start tap). The game answers `armed {needsTap}`: with `needsTap` the ready caption shows the armed cost and the player taps or clicks the frame, or presses Space or Enter while it has focus (activation and audio unlock happen in the iframe). The game then sends `startRequested`; the shell calls run start (spec 02 `POST /runs`) with the armed payment and, when required, a challenge token. Success: `start` with spec 03's payload from the response, plus the view `target` when the response carries one (spec 04 UX-G09). Failure: `startFailed {code, retryable}` and the mapped error (12.5); nothing is consumed. After `start`, `stage.getReady` with `game.{id}.hint` shows until `playing`.

UX-RUN-4: only a tap on the S3 primary, a pay option or S9 Play again arms a payment (`free` in gate free, `ad` in adReady, `points` after UX-PAY-2, `practice` after Practice); `weeklyBest` in `arm` is my verified best this week or null. Until armed, the S3 panel covers the frame and captures pointer events. Arming ends when S2 unmounts or a run ends.

| State | Shell UI | Next |
|---|---|---|
| idle | S2 + S3 | Play (armed): opening |
| opening | overlay `showModal()`, push `#play`, `p2e-game-mode-change {active:true}` | loading or ready |
| loading | cover, progress bar, `stage.loading` | ready; loadError after `runs.loadTimeoutMs` or game `error` |
| loadError | `game.loadFailed`, Retry (recreates the iframe), Close | idle |
| ready | on `armed {needsTap}`: caption + cost line when `needsTap`; `ArcadeHost.focus()` | `startRequested`: starting (ranked) or playing (practice) |
| challenge | bot-check sheet (spec 03) | token: starting; Cancel: ready |
| starting | `stage.starting` | ok: getReady; error: ready + notice |
| getReady | `stage.getReady` (`pointer-events: none`) | `playing` |
| playing | HUD pause button; Practice chip in practice | `paused`; `gameOver`: submitting |
| paused | pause menu, playfield hidden | Resume (game runs 3-2-1); End run: confirm, `endRun` |
| submitting | submit starts on `gameOver`; S9 opens on `overDone`, or `runs.overDoneFallbackMs` after `gameOver`, with local score and `saving` | answer: result; network or 5xx: queued |
| result | S9 complete | Play again (UX-RUN-3); Close: idle, `p2e-game-mode-change {active:false}` |

UX-RUN-5 pause: the pause button (44 x 44 px, top-left in the safe area), the first Back (`popstate` on `#play`, re-pushed) and dialog `cancel` (Esc, Android back via CloseWatcher; always `preventDefault()`) send `pause {reason:'user'}`; shell modals over a run send `overlay`; native backgrounding sends `app`; phone landscape (`(orientation: landscape) and (max-height: 500px)`) shows the rotate prompt and pauses. The game pauses itself on P, Esc and hidden. Every `paused` opens the pause menu with `stage.pausesLeft` from `pausesLeft`; Back while paused opens the leave confirm.

UX-RUN-6: End run and Leave send `endRun` (the run ends as `quit`, its score is submitted). `beforeunload` is registered only while a ranked run is playing or paused; shell links during a run open `game.leaveConfirm`; page hide follows spec 03 SDK-PRS. UX-RUN-7 practice: armed `practice`, a local random seed (R1.9), or the current ranked course when `practice.weeklyCourseAfterRankedRun` is on and the user already ran it (seed from spec 02); nothing is submitted; Practice chip; never convertible to ranked; practice best in localStorage.

UX-RUN-8 commitments (spec 03 SEC-AC-15, SEC-AC-16): the stage posts every `commit` message at once through `@pg/client` to spec 02's commit endpoint (`POST /runs/{runId}/commit`, run token, body `{seq, tick, kind, digest}`, `Idempotency-Key: commit-{runId}-{seq}`, `pause` with `keepalive`), never blocking play. Failed sends stay in the run's queue entry and are retried in `seq` order before the submission, never dropped; late ones only lead to review and never show an error.

### 5.2 Points try

UX-PAY-1: "Play for {cost} points" re-reads `TryStatus` (cache bypass), applies UX-PAY-2, then arms `points`; the debit happens at run issue, so leaving before the start spends nothing.

UX-PAY-2 (R1.3, PAY-3): S5 appears when `TryStatus.confirm` is true; Confirm starts with `payment {method:'points', expectedPrice, confirmed: true, dontAskAgainToday}` (the checkbox). The flag lives on the server, is shared by web and app, ends at the daily reset, and the UI stores no copy. When `confirm` is false the start sends `confirmed: false`; `CONFIRMATION_REQUIRED` opens S5. `prefs.confirmPaid = 'always'` hides the checkbox.

### 5.5 Submit queue (UX-SUB)

UX-SUB-1: one persisted queue, IndexedDB store `pg.v1.submits` in `@pg/client` (spec 02 RUN-A11), keyed by runId. An entry holds the run token, the idempotency key `submit-{runId}`, the latest snapshot or the final replay as raw P2RP bytes (spec 03 writes snapshots through `ArcadeHost`) and unsent commitments; the UI store `submitQueue` wraps it. Entries leave only on a definitive answer; retries follow `runs.submitRetryDelaysMs`, then `online`, focus and the next load; `pagehide` uses `keepalive` when the body is at most 60 KiB.

UX-SUB-2: submits use the run token, so host logout or CSRF expiry never loses a run; a 401 on a user call keeps the entry, emits `p2e-login-required {reason:'save'}` and resumes after login. A repeated submission returns the stored result (SET-11) and counts as success; late successes toast `result.savedLater`. UX-SUB-3: `run.reason = LATE` or a deadline problem (12.5) shows `result.status.tooLate` and removes the entry. UX-SUB-4: an interrupted run found on load shows `state.interrupted` or `state.interruptedLost` (spec 03 SDK-PRS-04).

## 12. Copy

### 12.1 Rules

Friendly, short, second person, sentence case, digits for numbers, at most one exclamation mark per message. EN lengths: buttons ≤ 28 characters (only `start.appPromo`, fixed by R1.6, wraps), toasts ≤ 80, notices ≤ 110, helpers ≤ 90 (claim and disclosure lines ≤ 140). Errors say what happened, what it cost, what to do next. No em dash characters in any catalog, spec or code comment (CI lint).

UX-COPY-1 banned in player catalogs (case-insensitive, whole words and plurals; CI fails): bet, wager, stake, gamble, gambling, casino, jackpot, lottery, raffle, draw, odds, luck, lucky, chance, cash, money, profit, prize, pot, slot, spin, buy-in, entry, guaranteed, risk-free, crypto, cryptocurrency, USDT, USD, dollar, token, coin, ticket, credit, life, lives; phrases "prize pool", "entry fee", "free money", "earn points by watching", "earn crypto", "free ad try". "free" never describes ad tries. The Official Rules may use legal terms (prize, contest, sponsor, entry), never casino terms.

UX-COPY-2: bonus text only from `bonus.*`; the explainer carries the owner's sentence verbatim. UX-COPY-3: before every ad, state the action, the reward (1 try for this game, never points), the forfeit rule (closing early means no try) and the count left. UX-COPY-4: copy never promises an ad (B1): ad mentions say "when available" and use live counts. `how.3` and `faq.more.a` select on `offer` from the pure helper `moreTriesOffer()`: `webApp` (web, points here, promo allowed), `web` (web, no promo), `pointsAd`, `ad`, `points` (app, by what is available here), `other`. ## Concerns for orchestrator

1. Spec 01's revision settled the D26 line statuses AWAITING_IDENTITY and UNCLAIMED (spec 02 `awaiting_identity`, `unclaimed`), `ADS_REGION_UNAVAILABLE` (spec 07 reason `REGION_NO_ADS`), `settlement.approvalAbovePoints`, `TryStatus.confirm`, `expectedPrice` and the analytics value `extra`, all as used here. Spec 02 still has to adopt them and name the claim recheck endpoint (the findings proposed `POST /me/payouts/recheck` and `POST /me/claims/refresh`).
2. Specs 01, 03 and 07 all recommend practice on the current ranked course after the first ranked run; they differ on the course period (spec 01 `dailyCourse`, specs 03 and 07 `weeklyCourse`, spec 03 adding `perRun` per game on evidence). The owner gets one question (PLAN.md); the UI supports every answer. (Corrected in the final consistency check: an earlier revision cited a spec 03 open decision 6, which does not exist.)
3. Spec 03 SDK-LC-06 and XS-09 set an 800 ms `overDone` fallback, which would cover the `sky-slabs` reveal (up to 2,500 ms). This spec uses `runs.overDoneFallbackMs = 3000`, which only matters when a game never sends `overDone`; better, spec 03 adds `overAnimMs` to `PublicMeta` so the fallback can be `overAnimMs + 500`.
4. Spec 04 UX-G09 puts `target?` in `ViewStartContext` and expects it from the run start, but spec 03's `ViewStartContext` and `start` have no such field yet; UX-RUN-3 forwards it once spec 03 names it.
5. With no third-party scripts on Playground pages (spec 02 SEC-A49), the host `gtag` that spec 02 section 13 names as the default client analytics sink is absent there; spec 02 should name the destination.
6. Size: this file is about 84 KB and `06-ux-copy.md` about 24 KB (pre-review: one 98 KB file). The catalog moved out, as spec 01 did with its vectors, without changing any key or rule; the rest of the growth is the applied findings (D26 claim flow, status map, two-person admin, host routes, commitments, analytics, error registry).
